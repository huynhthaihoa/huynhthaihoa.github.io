PyTorch Knowledge Distillation Tutorial

브레인스토밍

머신러닝의 knowledge distillation 맥락에서, 교사 모델(teacher model)과 학생 모델(student model)을 병렬로 함께 학습시키는 것은 일반적으로 표준적이거나 가장 효과적인 접근 방식은 아닙니다. 다만 목표와 제약 조건에 따라 특정 시나리오에서는 타당할 수 있습니다.

1. 표준 Knowledge Distillation 프로세스

Knowledge distillation은 일반적으로 두 단계로 이루어진 프로세스를 거칩니다:

  1. 교사 모델 학습: 크고 복잡한 모델(교사)을 사용 가능한 데이터셋으로 목표 과제(task)에 대해 먼저 학습시킵니다. 교사 모델은 대체로 과도하게 매개변수화(overparameterized)되어 있어 높은 성능을 달성하지만, 계산 비용이 클 수 있습니다.
  2. 학생 모델 학습: 그다음 더 작고 효율적인 모델(학생)을 교사의 동작을 모방하도록 학습시킵니다. 이는 교사의 출력(예: 완화된(softened) 로짓이나 특징 표현)을 소프트 타깃(soft target)으로 사용하여, ground-truth 레이블에 추가하거나 그 대신 사용함으로써 이루어집니다. 학생은 distillation loss(예: 교사와 학생의 출력 사이의 Kullback-Leibler divergence)와, 흔히 태스크별 손실(예: ground-truth 레이블과의 cross-entropy)을 포함한 손실 함수를 최소화하도록 학습됩니다.

교사는 학생을 학습시키는 동안 보통 사전 학습되고 고정되는데, 그 목적이 교사가 학습한 지식을 학생에게 전달하는 데 있기 때문입니다. 교사의 출력은 단순한 하드 레이블만으로는 얻을 수 없는 더 풍부한 지도(supervision) 신호를 제공합니다(예: 소프트 확률을 통해 클래스 간 관계를 포착).

2. 병렬 학습이 흔하지 않은 이유

교사와 학생 모델을 병렬로 학습시키는 것(즉, 학습 중 두 모델을 동시에 업데이트하는 것)은 다음과 같은 몇 가지 이유로 표준적인 방식이 아닙니다:

  1. 교사의 안정성: 교사 모델은 학생을 이끌어줄 신뢰할 수 있고 품질 높은 출력을 제공해야 합니다. 교사가 아직 학습 중이어서 파라미터가 계속 변화하고 있다면, 그 출력이 잡음이 많거나 일관되지 않을 수 있으며, 이는 학생의 학습 과정을 불안정하게 만들 수 있습니다.
  2. 계산 오버헤드: 두 모델을 동시에 학습시키면 두 모델 모두 순전파와 역전파를 수행해야 하므로 계산 요구량이 늘어납니다. Knowledge distillation은 효율성을 위해 가벼운 학생 모델을 만드는 것이 목적인데, 큰 교사 모델을 병렬로 학습시키는 오버헤드를 더하는 것은 이 목표에 반합니다.
  3. 목표 불일치: 교사는 대체로 태스크 성능(예: cross-entropy loss 최소화)에 맞춰 최적화되는 반면, 학생은 교사의 출력을 모방하도록(distillation loss) 그리고 선택적으로 ground-truth 레이블에 맞춰 최적화됩니다. 두 모델을 동시에 최적화하면 그래디언트나 목표가 충돌하여 수렴이 더 어려워질 수 있습니다.
  4. 순차적 의존성: 학생은 교사의 지식에 의존하는데, 이는 교사가 이미 좋은 해(solution)로 수렴했을 때 가장 효과적입니다. 병렬로 학습시키면 교사가 아직 전달할 만한 신뢰할 수 있는 지식을 갖추지 못했을 수 있으므로 이러한 의존 관계가 약화됩니다.

병렬 학습이 타당할 수 있는 시나리오

교사와 학생을 병렬로 학습시키는 것을 고려할 수 있는 특정한 경우들이 있지만, 이는 덜 흔하며 보통 표준 distillation 프레임워크에 변형을 가하는 것을 수반합니다:

  1. Online Knowledge Distillation (OKD): online distillation(예: Deep Mutual Learning과 같은 방법에서 제안된 방식)에서는 여러 모델(엄격한 교사-학생 위계라기보다는 동료(peer)로 볼 수 있음)이 동시에 학습되며 서로의 출력으로부터 배웁니다. 사전 학습된 교사 대신, 모든 모델이 교사이자 학생 역할을 동시에 수행하며 예측을 통해 지식을 공유합니다. 사용 사례: 사전 학습된 교사에 대한 접근이 제한된 시나리오, 또는 일반화 성능을 높이기 위해 비슷한 용량(capacity)의 여러 모델을 학습시키는 경우.
  2. 동적 교사 업데이트: 일부 설정에서는 학생의 필요에 맞추거나 새로운 데이터를 반영하기 위해 학습 중에 교사 모델을 미세조정(fine-tune)하거나 업데이트할 수 있습니다. 이는 교사가 여전히 안정적인 지식 원천으로 남도록 신중한 설계가 필요합니다. 예를 들어 교사에 더 느린 학습률을 사용하거나 업데이트를 교대로 진행하는 방식입니다. 사용 사례: Continual learning, online learning, 또는 교사를 사전 학습시키는 것이 현실적으로 어려운 스트리밍 데이터 시나리오.
  3. 효율성을 위한 Co-Training: 계산 자원이 허용된다면, 순차 학습에 비해 총 학습 시간을 줄이기 위해 병렬 학습을 탐구해볼 수 있습니다. 예를 들어 교사와 학생이 (공유된 특징 추출 백본처럼) 일부 계산 그래프를 공유하여 자원을 절약할 수 있습니다. 사용 사례: 학습 시간이 병목인, 자원이 풍부한 환경.
  4. 강화학습 또는 적대적 설정: GAN이나 강화학습(reinforcement learning)에서 영감을 받은 일부 고급 설정에서는 교사와 학생을 경쟁적으로 또는 협력적으로 학습시킬 수 있습니다. 사용 사례: 새로운 학습 동역학이나 적대적 지식 전달을 탐구하는 연구 환경.

병렬 학습의 과제

  • 교사 출력 안정화: 학습 초기에는 교사의 출력이 잡음이 많을 수 있으므로, 출력 스무딩, 교사 앙상블, 또는 distillation 지연 같은 기법이 필요할 수 있습니다.
  • 목표 균형 맞추기: 교사와 학생은 서로 다른 학습률, 손실 가중치, 또는 목표를 가질 수 있어 신중한 튜닝이 필요합니다.
  • 복잡도 증가: 병렬 학습은 더 많은 메모리와 연산을 필요로 하며, 큰 교사 모델에서는 실현 가능하지 않을 수 있습니다.
  • 평가 지표: 교사가 유용한 지식을 제공할 준비가 되었는지를 어떻게 평가할지 정의해야 합니다.

대안적 접근 방식

  • Self-Distillation: 학생 모델이 별도의 교사가 아니라 자기 자신(예: 이전 레이어나 이전 epoch)으로부터 지식을 증류합니다.
  • 사전 학습된 교사 재사용: BERT 같은 foundation model이나 공개된 체크포인트 등 기존에 사전 학습된 모델을 교사로 사용합니다.
  • Online Distillation 변형들: 고정된 교사-학생 위계 없이 여러 모델이 함께 학습하는 Deep Mutual Learning이나 Collaborative Learning과 같은 방법을 탐구합니다.

실용적 권장 사항

대부분의 경우, 순차 학습(교사를 먼저 사전 학습시킨 뒤 학생을 학습시키는 방식)이 knowledge distillation에서 가장 효과적이고 단순한 접근 방식입니다. 이는 교사가 안정적이고 품질 높은 출력을 제공하도록 보장하며, 효율적인 학생 모델을 만드는 것과도 부합합니다. 병렬 학습은 연구 환경이나 특정 사용 사례(예: online distillation이나 continual learning)에서 탐구해볼 수 있지만, 위에서 설명한 과제들을 다루기 위한 신중한 설계가 필요합니다.

3. 같은 데이터셋으로 교사를 사전 학습시키고 학생을 학습시키는 것이 타당한 이유

데이터 분포의 일관성

교사와 학생 모두에 같은 데이터셋을 사용하면 전달되는 지식이 학생이 실제로 마주치게 될 태스크와 데이터 분포에 관련성을 갖도록 보장할 수 있습니다. 교사는 데이터셋의 패턴, 관계, 구조를 학습하며, 학생은 이렇게 학습된 표현을 모방함으로써 이득을 얻습니다. 만약 교사가 다른 데이터셋으로 학습되었다면, 그 지식이 학생의 목표 데이터셋으로 잘 일반화되지 않아 최적에 못 미치는 성능으로 이어질 수 있습니다.

고품질 기준점으로서의 교사

같은 데이터셋으로 교사 모델을 사전 학습시키면 교사가 태스크에 대한 풍부한 정보를 포착하는 고성능 해(solution)로 수렴할 수 있습니다(예: 클래스 확률, 특징 표현, 결정 경계). 그러면 학생은 하드 레이블만으로는 얻을 수 없는 더 많은 정보를 제공하는 교사의 소프트 출력(예: 완화된 로짓이나 중간 특징)을 통해 이 고품질 지식을 활용할 수 있습니다. 예를 들어 분류(classification) 태스크에서는, (temperature 파라미터가 적용된) 교사의 softmax 출력이 클래스 간 관계를 드러내어 학생이 더 미묘한 결정 경계를 학습하도록 돕습니다.

Knowledge Distillation에서의 표준 관행

Hinton et al. (2015)이 제시한 정통적인 knowledge distillation 프레임워크는 교사가 목표 데이터셋에서 사전 학습되고, 학생이 같은 데이터셋에서 교사의 출력을 맞추도록 학습된다고 가정합니다. 이 설정은 이미지 분류, 자연어 처리, 음성 인식 등을 위한 모델 압축과 같은 응용 분야에서 널리 사용됩니다. 학생은 일반적으로 같은 데이터셋에서 distillation loss(예: 교사와 학생 로짓 사이의 KL divergence)와 태스크별 손실(예: ground-truth 레이블과의 cross-entropy)을 조합하여 최적화합니다.

데이터의 효율적인 활용

많은 실제 시나리오에서 데이터셋은 고정되어 있고 제한적입니다. 두 모델 모두에 같은 데이터셋을 사용하면 추가 데이터 수집이 필요하거나 도메인 불일치(domain mismatch)의 위험을 감수할 필요가 없습니다. 교사는 데이터셋에서 가능한 한 많은 지식을 추출하고, 학생은 이 지식을 더 소형화된 모델로 증류합니다.

이 접근 방식의 이점

  • 향상된 학생 성능: 학생은 교사가 학습한 지식으로부터 이득을 얻으며, ground-truth 레이블만으로 학습했을 때보다 더 나은 성능을 달성하는 경우가 많습니다.
  • 일반화: 교사의 소프트 타깃은 일종의 정규화(regularization) 역할을 하여, 학생이 더 매끄러운 결정 경계를 학습함으로써 더 잘 일반화하도록 돕습니다.
  • 유연성: 이 접근 방식은 분류, 회귀, 시퀀스 모델링 등 다양한 태스크와 모델 아키텍처에 걸쳐 적용될 수 있습니다.
  • 데이터 효율성: 레이블이 있는 데이터가 제한적이더라도 교사의 출력이 추가적인 지도(supervision)를 제공하여 학생이 더 효과적으로 학습하기 쉬워집니다.

고려 사항 및 모범 사례

  1. 교사 품질: 교사는 잘 학습되어야 하고 데이터셋에서 좋은 성능을 내야 합니다. 제대로 학습되지 않은 교사는 잡음이 많거나 신뢰할 수 없는 출력을 제공하여 학생 성능이 최적에 미치지 못하게 만듭니다.
  2. Distillation Loss 설계: 학생의 손실 함수는 대체로 distillation loss(교사의 출력에 맞추기)와 태스크별 손실(ground-truth 레이블에 맞추기)을 결합합니다. 이 균형(가중치 하이퍼파라미터로 제어되며, 예: L = α * L_distillation + (1-α) * L_task에서의 α)이 매우 중요합니다. softmax 함수의 temperature 파라미터 역시 튜닝이 필요한데, temperature가 높을수록(예: T = 2 또는 T = 4) 교사의 출력이 더 매끄러워집니다.
  3. Overfitting 위험: 데이터셋이 작으면 교사가 overfit될 수 있습니다. 교사 학습 시 정규화 기법(예: dropout, weight decay)과 데이터 증강(data augmentation)을 사용하고, 교사의 일반화 성능을 모니터링하세요.
  4. 데이터셋 크기와 다양성: 데이터셋이 매우 작으면 교사의 지식이 제한적일 수 있습니다. 사전 학습된 교사를 사용하거나 데이터셋을 증강하는 것을 고려하세요.
  5. 모델 아키텍처 호환성: 교사와 학생 모델이 출력 공간(output space) 측면에서 호환되는지 확인하세요. 학생이 다른 아키텍처를 사용한다면 feature-based distillation 같은 추가 기법이 필요할 수 있습니다.
  6. 계산 효율성: 교사는 이미 사전 학습되어 있으므로 학생 학습 중 파라미터가 고정됩니다. 학생은 교사의 출력만 필요로 하며, 이는 전체 데이터셋에 대해 미리 계산하여 캐싱함으로써 시간을 절약할 수 있습니다.

잠재적 대안 또는 변형

  • Transfer Learning 또는 Domain Adaptation: 교사가 (ImageNet 같은) 더 크고 관련된 데이터셋으로 사전 학습되어 있다면, distillation 전에 목표 데이터셋으로 미세조정할 수 있습니다.
  • 레이블이 없거나 증강된 데이터: 경우에 따라 학생을 레이블이 있는 데이터와 없는 데이터가 섞인 데이터로 학습시킬 수 있으며, 이때 교사가 레이블이 없는 데이터에 대해 pseudo-label(가짜 레이블)을 제공합니다.
  • Online Distillation: 교사의 사전 학습을 아예 피하고 싶다면 online knowledge distillation(예: Deep Mutual Learning)을 탐구해볼 수 있습니다.

실용적 예시

CIFAR-10 데이터셋으로 이미지 분류 태스크를 진행한다고 가정해봅시다:

  • 교사 학습: 큰 모델(예: ResNet-50)을 CIFAR-10에서 (예: 테스트셋 기준 95%처럼) 높은 정확도를 달성할 때까지 학습시킵니다.
  • 학생 학습: 더 작은 모델(예: MobileNet)을 CIFAR-10에서, 교사의 완화된 로짓(temperature T=4)과 학생의 로짓 사이의 KL divergence, 그리고 ground-truth 레이블과의 cross-entropy loss를 결합한 손실 함수로 학습시킵니다.
  • 결과: 학생은 훨씬 더 작고 빠르면서도 교사와 근접한 정확도(예: 93%)를 달성합니다.

4. 서로 다른 데이터셋을 사용하는 경우

4.1. Transfer Learning 또는 Domain Adaptation

  • 시나리오: 교사는 크고 일반적인 데이터셋(예: 이미지의 경우 ImageNet, 텍스트의 경우 Wikipedia나 Common Crawl)으로 사전 학습되고, 학생은 더 작고 태스크나 도메인에 특화된 데이터셋으로 학습됩니다.
  • 근거: 흔히 큰 foundation model인 교사는 다양한 데이터셋으로부터 폭넓고 일반화 가능한 특징을 학습합니다. 이러한 특징은 목표 데이터셋이 제한적이더라도 특정 도메인이나 태스크에 맞춘 더 작은 학생 모델로 증류될 수 있습니다.
  • 예시: NLP에서 BERT와 같은 교사는 거대한 텍스트 코퍼스(예: Wikipedia + BookCorpus)로 사전 학습됩니다. 학생(예: DistilBERT)은 더 작고 태스크에 특화된 데이터셋(예: IMDb 리뷰의 감성 분석)으로, 교사의 출력을 학습 지침으로 삼아 학습됩니다.
  • 이점: 교사의 일반적인 지식을 활용해, 데이터가 제한적인 전문 태스크에서 학생의 성능을 향상시킵니다.
  • 과제: 교사의 지식이 목표 도메인과 완전히 부합하지 않을 수 있어, distillation 과정을 신중하게 튜닝해야 합니다.

4.2. 레이블 없는 데이터를 활용한 Semi-Supervised Learning

  • 시나리오: 교사는 레이블이 있는 데이터셋으로 학습되고, 학생은 같은 레이블 데이터셋과 추가적인 레이블 없는 데이터를 결합한 데이터로 학습되며, 레이블 없는 부분에는 교사의 예측(pseudo-label)을 사용합니다.
  • 근거: 교사는 레이블 없는 데이터에 대해 고품질 pseudo-label을 제공하여 사실상 학생의 학습 데이터셋을 확장합니다. 레이블 데이터가 부족하지만 레이블 없는 데이터는 풍부한 경우 특히 유용합니다.
  • 예시: 이미지 분류에서, 교사는 CIFAR-100의 레이블이 있는 부분집합으로 학습됩니다. 학생은 이 레이블 부분집합과 레이블 없는 대규모 이미지 풀 모두로 학습됩니다.
  • 이점: 레이블 없는 데이터를 활용하여 학생의 성능을 향상시킵니다.
  • 과제: 특히 분포 밖(out-of-distribution)의 레이블 없는 데이터에서는 교사의 pseudo-label에 오류가 있을 수 있으며, 신뢰도 임계값(confidence thresholding)이나 일관성 정규화(consistency regularization)가 필요할 수 있습니다.

4.3. 프라이버시 보호 또는 데이터 제약 환경

  • 시나리오: 교사는 공유할 수 없는 민감하거나 독점적인 데이터셋으로 학습되고, 학생은 다른, 공개적으로 이용 가능하거나 합성된 데이터셋으로 학습됩니다.
  • 근거: Knowledge distillation을 사용하면 원본 학습 데이터를 직접 노출하지 않고도 교사의 지식을 전달할 수 있습니다.
  • 예시: 비공개 의료 기록으로 학습된 교사 모델을 사용해, 합성되었거나 공개된 의료 데이터셋으로 학습되는 학생 모델에 지식을 증류합니다.
  • 이점: 엄격한 데이터 프라이버시나 접근 제한이 있는 환경에서도 지식 전달을 가능하게 합니다.
  • 과제: 효과적인 distillation을 위해서는 대리(proxy) 데이터셋이 교사의 데이터셋과 충분히 유사해야 합니다.

4.4. 데이터 증강 또는 변형된(perturbed) 데이터셋

  • 시나리오: 교사는 원본 데이터셋으로 학습되고, 학생은 (잡음 추가, 변환, 적대적 예제 등이 더해진) 증강되거나 변형된 버전으로 학습됩니다.
  • 근거: 학생을 증강된 데이터로 학습시키면 강건성(robustness)이나 일반화 성능을 향상시킬 수 있으며, 교사는 안정적이고 품질 높은 타깃을 제공합니다.
  • 예시: 컴퓨터 비전에서, 교사는 원본 그대로의 ImageNet 이미지로 학습되고, 학생은 무작위 증강(회전, 뒤집기, 색상 지터)이 적용된 ImageNet으로 학습됩니다.
  • 이점: 입력 데이터의 변동에 대한 학생의 강건성을 높입니다.
  • 과제: 무관하거나 해로운 잡음이 유입되지 않도록 증강 기법을 신중하게 선택해야 합니다.

4.5. Cross-Modal 또는 Multi-Task Distillation

  • 시나리오: 교사는 하나의 모달리티(modality)나 태스크로 학습되고, 학생은 다른 모달리티나 태스크로, 공유되거나 정렬된(aligned) 지식을 이용해 학습됩니다.
  • 근거: 한 도메인이나 모달리티에서 얻은 교사의 지식은, 특히 태스크들이 근본적인 패턴을 공유할 때, 관련은 있지만 다른 도메인에서 학생을 이끌어줄 수 있습니다.
  • 예시: vision-language 모델에서, 대규모 이미지-캡션 데이터셋으로 학습된 교사가 특정 태스크를 위해 텍스트 전용 또는 이미지 전용 데이터셋으로 학습되는 학생에게 지식을 증류합니다.
  • 이점: 모달리티나 태스크를 넘나드는 지식 전달을 가능하게 합니다.
  • 과제: 교사와 학생의 출력 공간 사이의 정렬이 필요하며, 흔히 추가적인 매핑 레이어나 손실 함수가 요구됩니다.

4.6. Continual Learning 또는 변화하는 데이터 분포

  • 시나리오: 교사는 초기 데이터셋으로 학습되고, 학생은 변화하거나 갱신된 데이터 분포를 반영하는 새로운 데이터셋으로 학습됩니다.
  • 근거: 교사는 원본 데이터로부터 안정적인 지식 기반을 제공하고, 학생은 새로운 분포에 적응합니다.
  • 예시: 추천 시스템에서, 교사는 과거의 사용자 상호작용 데이터로 학습되고, 학생은 새로운 사용자 행동이나 아이템이 반영된 최근 데이터로 학습됩니다.
  • 이점: 이전 지식을 보존하면서도 변화하는 환경에 대한 적응을 지원합니다.
  • 과제: 교사의 지식이 오래될 수 있으므로, 교사를 미세조정하거나 여러 교사의 앙상블을 사용하는 등의 기법이 필요할 수 있습니다.

서로 다른 데이터셋을 사용할 때의 고려 사항

  1. 도메인 정렬(Domain Alignment): 교사의 지식이 학생의 태스크와 관련성을 갖도록 데이터셋들이 충분히 연관되어 있어야 합니다. Feature alignment나 adversarial training과 같은 기법이 도메인 차이를 좁히는 데 도움이 될 수 있습니다.
  2. 교사 출력 품질: 교사의 출력은 학생의 데이터셋에 대해 신뢰할 수 있어야 합니다. 학생 데이터셋의 일부에 대해 교사 성능을 검증하거나, 신뢰도 기반 필터링으로 품질이 낮은 예측을 걸러내세요.
  3. Distillation Loss 설계: distillation loss는 데이터 분포의 잠재적 차이를 고려해야 합니다. 교사의 출력이 덜 신뢰할 만할 때는 distillation loss의 가중치를 태스크별 손실보다 낮게 두는 것이 도움이 될 수 있습니다.
  4. 데이터 가용성과 프라이버시: 학생의 데이터셋이 학습에 충분한지 확인하고, 프라이버시에 민감한 경우에는 distillation 과정이 (GDPR이나 HIPAA 같은) 데이터 규정을 준수하는지 검증하세요.
  5. 평가 및 검증: 학생의 목표 데이터셋에서 나온 검증 세트로 성능을 모니터링하고, distillation 없이 학습된 baseline과 비교하세요.

서로 다른 데이터셋을 피해야 할 때

서로 다른 데이터셋을 사용하면 복잡성과 위험이 생길 수 있습니다. 다음의 경우라면 이 접근 방식을 피하세요:

  • 데이터셋들이 서로 무관하거나 도메인 격차가 크며, 교사를 미세조정하는 것이 실현 가능하지 않은 경우.
  • 학생의 데이터셋이 크고 품질이 높아, 다르게 학습된 교사로부터의 distillation이 불필요한 경우.
  • 학생의 데이터 분포에 대한 교사의 성능이 좋지 않고, 이를 검증하거나 개선할 방법이 없는 경우.

5. Self-Training

Self-Training이란?

Self-training은 (흔히 교사라고 불리는) 모델을 먼저 레이블이 있는 데이터셋으로 학습시킨 뒤, 이를 사용해 레이블 없는 데이터셋에 대한 pseudo-label을 생성하는 semi-supervised learning 접근 방식입니다. 이 pseudo-label들은 레이블 데이터와 결합되어 (흔히 학생이라 불리는) 새로운 모델을 학습시키는 데 사용되며, 이 모델은 같은 아키텍처일 수도, 다른 아키텍처일 수도 있습니다. 이 과정은 반복적일 수 있으며, 이후 라운드에서는 학생이 교사가 됩니다.

Self-Training의 작동 방식

  1. 교사 학습: 레이블이 있는 데이터셋 $D_L = \{(x_i, y_i)\}$로 모델을 학습시킵니다. 여기서 $x_i$는 입력, $y_i$는 ground-truth 레이블입니다.
  2. Pseudo-Label 생성: 학습된 교사를 사용해 레이블 없는 데이터셋 $D_U = \{(x_j)\}$에 대한 레이블(또는 확률)을 예측합니다. 이 예측들을 pseudo-label이라 하며 $\hat{y}_j$로 표기합니다.
  3. 고신뢰도 Pseudo-Label 선택: 흔히 (임계값 이상처럼) 신뢰도가 높은 pseudo-label만 사용해 잡음이 많은 예측을 걸러냅니다.
  4. 학생 학습: 결합된 데이터셋 $D_L \cup \{(x_j, \hat{y}_j)\}$로 새로운 모델을 학습시키며, 학생은 ground-truth 레이블과 pseudo-label 모두로부터 학습합니다.
  5. 반복(선택 사항): 학생이 교사가 되어 새로운 pseudo-label을 생성하고, 이 과정이 여러 차례 반복됩니다.

Self-Training이 모델 성능을 향상시키는 방식

  • 레이블 없는 데이터 활용: Self-training은 풍부한 레이블 없는 데이터를 활용해 실질적인 학습 세트 크기를 늘리고, 모델이 더 강건한 특징을 학습하도록 돕습니다.
  • 정규화 효과: Pseudo-label은 일종의 정규화 역할을 하여, 모델이 레이블 데이터와 레이블 없는 데이터 전반에서 일관된 예측을 내도록 유도합니다.
  • 향상된 일반화: 모델을 더 크고 다양한 데이터셋에 노출시킴으로써, self-training은 분포 밖(out-of-distribution) 예제나 어려운 예제에 대한 성능을 향상시킬 수 있습니다.
  • 반복적 정제: 반복적인 self-training에서는 각 라운드가 pseudo-label을 정제하여, 그 품질을 개선할 가능성이 있습니다.

과제

  • 오류 전파: 교사의 pseudo-label이 잘못되어 있으면 학생이 잡음이 많거나 편향된 레이블로부터 학습할 수 있습니다. 신뢰도 임계값이나 소프트 레이블(확률)을 사용하면 이를 완화할 수 있습니다.
  • 제한된 교사 품질: 초기 교사가 작은 레이블 데이터셋으로 학습되었다면, 그 pseudo-label이 신뢰할 만하지 않을 수 있습니다.
  • 도메인 이동(Domain Shift): 레이블 없는 데이터가 레이블 데이터와 크게 다르면, pseudo-label이 목표 태스크와 맞지 않을 수 있습니다.

6. Noisy Student Training

Noisy Student Training이란?

Noisy Student Training(Xie et al., 2020)은 잡음과 정규화를 결합해 학생 모델의 성능을 교사의 성능 이상으로 향상시키는 고급 self-training 기법입니다. 표준 self-training과 달리, Noisy Student는 학생의 학습 과정에 (데이터 증강, dropout 등의) 확률적 요소를 명시적으로 추가하여 더 강건하게 만들고, 학생이 단순히 교사의 예측을 암기하는 것을 방지합니다.

Noisy Student Training의 작동 방식

  1. 교사 학습: self-training과 마찬가지로 레이블이 있는 데이터셋 $D_L$로 교사 모델을 학습시킵니다.
  2. Pseudo-Label 생성: 교사를 사용해 대규모 레이블 없는 데이터셋 $D_U$에 대한 pseudo-label을 예측합니다. 과정을 단순화하기 위해 소프트 레이블 대신 하드 레이블(클래스 예측)이 흔히 사용됩니다.
  3. 잡음을 더해 학생 학습: (보통 교사와 같거나 더 큰 용량의) 학생 모델을 $D_L \cup \{(x_j, \hat{y}_j)\}$로 학습시키되, 학습 중에 잡음과 정규화를 도입합니다:
    • 데이터 증강: 레이블 있는 입력과 없는 입력 모두에 (이미지의 경우 RandAugment 같은) 강한 증강을 적용합니다.
    • 모델 잡음: 학생 모델에 dropout, stochastic depth, 무작위 레이어 동결(freezing) 같은 기법을 사용합니다.
    • 균형 잡힌 데이터셋: 레이블이 있는 데이터와 없는 데이터가 균형을 이루도록 합니다.
  4. 반복: 학생을 새로운 교사로 사용해 갱신된 pseudo-label을 생성하고 이 과정을 반복합니다. 각 반복은 대체로 모델 성능을 향상시킵니다.

Self-Training과의 주요 차이점

  • 잡음 주입: Noisy Student는 교사의 pseudo-label에 overfitting되는 것을 막고 강건성을 높이기 위해 의도적으로 잡음을 추가합니다.
  • 동등하거나 더 큰 학생: 학생이 더 작은 knowledge distillation과 달리, Noisy Student는 흔히 교사와 동등하거나 더 큰 용량의 학생을 사용합니다.
  • 반복적 개선: Noisy Student는 여러 차례의 반복을 강조하며, 각 학생이 이전 교사보다 더 나은 성능을 낼 가능성이 있습니다.

Noisy Student가 모델 성능을 향상시키는 방식

  • 잡음을 통한 강건성: 추가된 잡음은 학생이 더 일반화 가능한 특징을 학습하도록 강제하여, 교사의 예측이나 pseudo-label의 편향에 overfitting되는 것을 방지합니다.
  • 레이블 없는 데이터에 따른 확장성: Noisy Student는 대량의 레이블 없는 데이터를 활용하며, 이는 데이터가 부족한 환경에서 성능을 향상시키는 데 매우 중요합니다.
  • 반복적 정제: 학생이 교사가 되면서 더 정확해짐에 따라 각 반복이 pseudo-label을 정제하여, 선순환적인 개선으로 이어집니다.
  • 교사를 뛰어넘기: 잡음, 더 큰 학생 모델, 반복 학습을 결합함으로써 Noisy Student는 초기 교사보다 더 뛰어난 모델을 만들어낼 수 있습니다.

예시

Noisy Student 논문에서는 EfficientNet 교사를 레이블이 있는 ImageNet 데이터셋으로 학습시켰습니다. 이 교사는 JFT-300M에서 가져온 3억 개의 레이블 없는 이미지에 대해 pseudo-label을 생성했습니다. 더 큰 EfficientNet 학생을 강한 증강(RandAugment)과 dropout을 적용해 결합된 데이터셋으로 학습시킨 결과, 교사보다 더 높은 정확도를 달성했습니다. 여러 차례 반복한 뒤, 최종 모델은 ImageNet에서 새로운 벤치마크를 세웠습니다.

과제

  • 계산 비용: Noisy Student는 큰 모델을 학습시키고 대규모 데이터셋에 대해 여러 차례 반복하는 과정을 포함하므로 상당한 계산 자원을 필요로 합니다.
  • 잡음 튜닝: 강건성과 학습 안정성 사이의 균형을 맞추기 위해 잡음(증강, dropout)의 종류와 강도를 신중하게 튜닝해야 합니다.
  • Pseudo-Label 품질: self-training과 마찬가지로, 특히 초기 반복에서 품질이 낮은 pseudo-label은 성능을 저해할 수 있습니다.

7. Knowledge Distillation 및 서로 다른 데이터셋과의 연관성

Self-training과 Noisy Student 모두 knowledge distillation과 밀접하게 연관되어 있으며, 특히 교사와 학생이 서로 다른 데이터셋(예: 레이블 있는 데이터 대 레이블 없는 데이터)으로 학습되는 시나리오에서 그렇습니다:

  • 서로 다른 데이터셋: 두 방법 모두에서 교사는 대체로 레이블이 있는 데이터셋으로 학습되고, 학생은 레이블 데이터셋과 레이블 없는 데이터셋(또는 pseudo-label이 붙은 다른 데이터셋)의 조합으로 학습됩니다.
  • 지식 전달: knowledge distillation과 마찬가지로, self-training과 Noisy Student는 (하드 또는 소프트) pseudo-label을 통해 교사에서 학생으로 지식을 전달합니다.
  • 성능 향상: 이 방법들은 레이블 데이터셋이 작지만 레이블 없는 데이터가 풍부할 때 특히 효과적입니다.

이 기법들이 모델 성능을 향상시키는 방식

  1. 데이터 활용도 증가: 두 방법 모두 흔히 풍부한 레이블 없는 데이터를 활용해 학습 세트를 확장합니다. 이는 모델을 더 다양한 패턴에 노출시켜 일반화 성능을 향상시킵니다.
  2. 정규화: Pseudo-label과 (Noisy Student의 경우) 잡음은 정규화 요소로 작용하여 레이블 데이터에 대한 overfitting을 방지합니다.
  3. 반복적 개선: 반복 학습은 pseudo-label을 정제하여 점진적으로 더 나은 모델로 이어집니다.
  4. 제한된 레이블 데이터 처리: 레이블이 있는 예제가 적은 환경에서, 이 방법들은 레이블 없는 데이터로 이를 보완하여 완전 지도 학습(fully supervised) 모델에 가까운 성능을 달성합니다.
  5. Domain Adaptation: 레이블 없는 데이터가 다소 다른 분포에서 나온 경우, 이 방법들은 학생이 목표 도메인에 적응하도록 도울 수 있습니다.

실용적 고려 사항

  • Self-Training을 사용할 때: Self-training은 소규모에서 중간 규모의 레이블 없는 데이터셋에 효과적이며, 계산 자원이 제한적이거나 학생 모델이 교사와 유사할 때 더 단순한 semi-supervised 태스크에 사용됩니다.
  • Noisy Student를 사용할 때: 대규모 레이블 없는 데이터셋에 접근할 수 있고 충분한 계산 자원이 있으며, 교사를 뛰어넘을 가능성까지 포함해 성능을 극대화하고 싶을 때 Noisy Student를 사용하세요.
  • 구현 팁:
    • 신뢰도 임계값: 잡음을 줄이기 위해 신뢰도로 pseudo-label을 필터링하세요(예: 확률이 > 0.9인 예측만 유지).
    • 강력한 교사: 신뢰할 수 있는 pseudo-label을 보장하기 위해 (대규모 데이터셋에서 사전 학습된 것 같은) 고품질 교사로 시작하세요.
    • 잡음 튜닝: Noisy Student에서는 (RandAugment 같은) 증강 정책과 정규화 강도를 실험해보세요.
    • 반복 전략: 오류 누적을 피하기 위해 반복 횟수를 제한하고, 필요하면 조기 종료할 수 있도록 검증 성능을 모니터링하세요.

1. 타원 실습 (Ellipse Playground)

이미지 좌표계 $Oxy$가 주어지고, $O(0, 0)$을 좌표 원점이라 할 때:

1.1. 일반 방정식

회전된 타원의 일반 방정식:

$$\frac{[(x-c_x)\cos(-\theta)+(y-c_y)\sin(-\theta)]^2}{a^2}+\frac{[(x-c_x)\sin(-\theta)-(y-c_y)\cos(-\theta)]^2}{b^2}=1$$

여기서:

  • $C(c_x, c_y)$는 타원의 중심입니다
  • $a, b$는 장반경과 단반경입니다
  • $\theta$는 $Cx$축(($Ox$축이 아님)으로부터 측정한 회전각입니다(시계 방향)

1.2. 매개변수 방정식

$$x(\alpha) = a\cos(\alpha)\cos(\theta) - b\sin(\alpha)\sin(\theta) + c_x$$ $$y(\alpha) = a\cos(\alpha)\sin(\theta) + b\sin(\alpha)\cos(\theta) + c_y$$

여기서:

  • $C(c_x, c_y)$는 타원의 중심입니다
  • $a, b$는 장반경과 단반경입니다
  • $\theta$는 $Cx$축(($Ox$축이 아님)으로부터 측정한 회전각입니다(시계 방향)
  • $\alpha$는 매개변수이며, $0$에서 $2\pi$까지의 범위(라디안)를 가집니다

회전된 타원의 도해입니다. $Cx$와 $Cy$는 각각 $Ox$, $Oy$와 평행하며 같은 방향을 공유합니다:

2. 점 회전 (Rotate Point)

점 $B(x_B, y_B)$를 점 $A(x_A, y_A)$ 중심으로 각도 $\theta$만큼(반시계 방향) 회전시키면 점 $C(x_C, y_C)$를 얻게 되며, 이때:

$$x_C = (x_B - x_A)\cos(\theta) - (y_B - y_A)\sin(\theta) + x_A$$ $$y_C = (x_B - x_A)\sin(\theta) + (y_B - y_A)\cos(\theta) + y_A$$

Python 구현:

def get_rotation(start_point, center_point, rad):
    """Rotate start_point around center_point by rad radians (counterclockwise).

    Args:
        start_point:  (x, y)
        center_point: (x, y)
        rad:          rotation angle in radians, counterclockwise

    Returns:
        [x_T, y_T]
    """
    T = [0, 0]
    T[0] = (start_point[0] - center_point[0]) * math.cos(rad) \
         - (start_point[1] - center_point[1]) * math.sin(rad) \
         + center_point[0]
    T[1] = (start_point[0] - center_point[0]) * math.sin(rad) \
         + (start_point[1] - center_point[1]) * math.cos(rad) \
         + center_point[1]
    return T

인간의 깊이 지각 (Depth Perception)

인간의 깊이 지각에 관한 문헌들은 거리를 추정하는 데 사용될 수 있는 회화적 단서(pictorial cue)에 대한 통찰을 제공합니다. 다음과 같은 단서들은 대체로 단일 이미지에서 발견할 수 있습니다:

  • 이미지 내 위치: 더 멀리 있는 물체는 지평선에 더 가까운 경향이 있습니다. 지면에 놓여 있을 때, 물체는 이미지에서 더 높게 나타나기도 합니다.
  • 가림 (Occlusion): 가까운 물체가 뒤에 있는 물체를 가립니다 — 깊이의 순서는 알 수 있지만 정확한 거리는 알 수 없습니다.
  • 텍스처 밀도 (Texture density): 더 멀리 있는 질감 있는 표면은 더 미세하게(fine-grained) 보입니다.
  • 선형 원근 (Linear perspective): 실제 세계의 직선이고 평행한 선들이 이미지에서는 수렴하는 것처럼 보입니다.
  • 물체의 겉보기 크기: 더 멀리 있는 물체는 더 작게 보입니다.
  • 움직임 효과 (Motion effect): 물체가 멀어질수록 흐려지고 푸르스름해집니다.
  • 음영 및 조명 (Shading & illumination): 표면의 법선(normal)이 광원을 향할 때 그 표면은 더 밝게 보입니다. 음영은 하나의 표면 내에서 깊이 변화에 대한 정보를 제공합니다.
  • 초점 흐림 (Focus blur): 초점 평면(focal plane)의 앞이나 뒤에 있는 물체는 흐리게 보입니다.
  • 대기 원근 (Aerial perspective): 매우 멀리 있는 물체는 대비(contrast)가 낮고 푸르스름한 색조를 띱니다.

깊이 추정 접근 방식

단안(monocular) 깊이 추정에는 2가지 접근 방식이 있습니다: 절대 깊이 추정과 상대 깊이 추정입니다.

1. 절대 깊이 추정

절대(또는 metric) 깊이 추정은 픽셀별 깊이 값을 절대적인 물리 단위(미터)로 예측합니다.

  • 장점: 예측 결과를 downstream 응용에 바로 사용할 수 있습니다.
  • 단점: 여러 데이터셋에 걸쳐 학습하면, 특히 (실내 대 실외처럼) 깊이 스케일이 크게 다를 때 성능이 저하되는 경우가 많습니다. 이러한 방법들은 대체로 특정 데이터셋에 overfit되는 경향이 있습니다.

2. 상대 깊이 추정

상대 깊이 추정은 스케일 요소를 배제하고, 픽셀들 사이의 상대적인 깊이를 추정합니다. 절대적인 스케일 계수는 알 수 없습니다.

  • 장점: 여러 도메인에 걸친 일반화를 가능하게 합니다 — metric 스케일과 카메라 파라미터가 일관될 필요가 없습니다.
  • 단점: 예측된 깊이는 metric 단위로서의 의미를 갖지 않습니다.

깊이 추정에서 3D 재구성으로

2D 좌표 $p$(이미지 평면)와 이에 대응하는 3D 좌표 $P_c$(카메라 좌표계) 사이의 관계는 다음과 같습니다:

$$s\,p = A P_c \quad (1)$$

여기서 $p = \begin{bmatrix} u\\ v \end{bmatrix}$, $P_c = \begin{bmatrix} X_c\\ Y_c \\ Z_c \end{bmatrix}$이고, $s$는 투영 스케일링 계수(projective scaling factor), $A$는 (이상적인) 카메라 내부 파라미터 행렬(intrinsic matrix)입니다:

$$A = \begin{bmatrix} f_x & 0 & c_x \\ 0 & f_y & c_y \\ 0 & 0 & 1 \end{bmatrix} \quad (2)$$

실제로는 모든 카메라에 렌즈 왜곡(distortion)이 있으므로, 먼저 캘리브레이션을 수행한 뒤 OpenCV를 통해 최적의 $A$를 계산합니다:

camera_matrix = np.zeros(shape=(3, 3))
camera_matrix[0, 0] = 3.618627944978409e+02
camera_matrix[0, 2] = 3.140828758355781e+02
camera_matrix[1, 1] = 3.611479934228698e+02
camera_matrix[1, 2] = 1.674230039961440e+02
camera_matrix[2, 2] = 1

dist_coeffs = np.array([-0.115065515143958, 0.023076954804581, 0, 0, 0])

# W, H = image width and height
A, _ = cv2.getOptimalNewCameraMatrix(camera_matrix, dist_coeffs, (W, H), 1)
💡 카메라 캘리브레이션은 근사 과정(approximation process)입니다 — machine learning과 유사합니다. 실제로 이상적인 카메라 행렬을 얻는 경우는 거의 없지만, 단순화를 위해 그 결과를 $A$로 취급합니다.

절대 깊이 맵은 $Z_c$를 제공합니다. 나머지 좌표는 (1)과 (2)로부터 유도됩니다:

$$X_c = \frac{Z_c(u - c_x)}{f_x} \quad (3) \qquad Y_c = \frac{Z_c(v - c_y)}{f_y} \quad (4)$$

Python 구현:

def depth_to_3d(D, fx, fy, cx, cy):
    """Convert absolute depth map to 3D coordinates in camera coordinate system.

    Args:
        D:  absolute depth map, shape (H, W)
        fx, fy: focal lengths; cx, cy: principal point

    Returns:
        3D coordinates, shape (H*W, 3) — each row is (Xc, Yc, Zc)
    """
    H, W = D.shape
    xx, yy = np.tile(range(W), H), np.repeat(range(H), W)
    Z = D.reshape(-1)
    Xc = (xx - cx) * Z / fx
    Yc = (yy - cy) * Z / fy
    return np.stack([Xc, Yc, Z], axis=1)

Pseudo-LIDAR로 LIDAR 재현하기

💡 이 제안을 검증하기 위해, CARLA 시뮬레이션 환경에 카메라 4대와 LIDAR 1대를 설치하고, 데이터를 기록한 뒤, end-to-end 파이프라인으로 실험합니다.

360° 포인트 클라우드(point cloud)를 생성하는 LIDAR $L$이 주어졌을 때, 카메라 $C_i$들을 사용해 이를 재현합니다. 제안하는 파이프라인:

  1. 각 이미지 $I_i$의 절대 깊이 맵 $D_i$를 추론합니다.
  2. $D_i$와 내부 파라미터 행렬 $A_i$를 사용해 각 카메라 좌표계에서 3D 좌표 $P_{C_i}$를 계산합니다.
  3. 회전 $R_i$와 평행이동 $t_i$를 통해 LIDAR 좌표계로 재투영(re-project)합니다:
    $$P_{L_i} = [R_i \mid t_i]\,P_{C_i} \quad (5)$$

실제 LIDAR 대비 장점: 더 낮은 비용, 더 밀도 높은 컬러 포인트 클라우드, 잠재적으로 더 높은 프레임 레이트.

단점: 카메라 왜곡의 한계, 조명과 날씨에 대한 민감성, 빈번한 가림(occlusion), 다중 카메라 스티칭(stitching)의 필요성, 그리고 어려운 캘리브레이션/동기화.

Perspective Transform과 Affine Transform

2025년 11월 24일

Perspective Transform

Homography(perspective transform)는 서로 다른 두 평면을 연결하는 기하학적 변환입니다. 변환 후에도 직선은 직선으로 유지됩니다.

평면 $\pi$ 위의 각 점 $(x, y)$는 평면 $\pi'$ 위의 $(x', y')$로 매핑됩니다:

$$s \begin{bmatrix} x' \\ y' \\ 1 \end{bmatrix} = \mathbf{H} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix} = \begin{bmatrix} h_{11} & h_{12} & h_{13} \\ h_{21} & h_{22} & h_{23} \\ h_{31} & h_{32} & h_{33} \end{bmatrix} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix}$$

여기서 $s$는 스케일 계수이고 $\mathbf{H}$는 8 자유도(DoF)를 갖는 3×3 homography 행렬입니다. $\mathbf{H}$를 계산하려면 4쌍의 대응점이 필요하며, 이 중 어느 3점도 한 직선 위에 있으면 안 됩니다.

Affine Transform

정의

Affine 변환(affine transformation)은 직선과 평행성을 보존하지만, 유클리드 거리와 각도까지 반드시 보존하지는 않습니다:

  • 같은 직선 위에 있는 점들은 변환 후에도 한 직선 위에 있습니다.
  • 평행한 직선들은 변환 후에도 평행을 유지합니다.
  • 임의의 두 선분의 비율이 보존됩니다; 중점은 변환 후에도 중점으로 유지됩니다.

예시

  • 평행이동 (Translation): 도형의 방향이나 크기를 바꾸지 않고 이동시킵니다.
  • 회전 (Rotation): 도형을 한 점을 중심으로 회전시킵니다.
  • 크기 조정 (Scaling): 도형을 확대하거나 축소합니다.
  • 기울이기 (Shearing): 도형을 비스듬히 기울입니다.

간단한 휴대폰 응시 감지 알고리즘

2025년 11월 24일

소개

객체 탐지 모델(Object Detection Model)과 시선 추정 모델(Gaze Estimation Model)이 주어졌을 때, 입력 이미지로부터 사람이 휴대폰을 보고 있는지 확인하는 간단한(naive) 알고리즘입니다.

아이디어

가정:

  • 객체 탐지 모델은 Phone과 Human 클래스의 객체를 탐지합니다.
  • 시선 추정 모델은 gaze_start에서 시작해 gaze_end를 향하는 gaze vector(시선 벡터)를 예측합니다.

사람은 하나의 광선(ray)만 보는 것이 아니라 원뿔 형태의 FOV(cone-like FOV)를 봅니다. 우리는 시선 FOV를 gaze vector를 각의 이등분선으로 갖는 원뿔로 정의한 뒤, 어떤 Phone 객체가 이 FOV와 교차하는지 확인합니다. 어떤 객체가 다음 조건을 만족하면 교차한다고 봅니다:

  1. 해당 객체의 신뢰도 점수(confidence score)가 conf_thres보다 높다(휴대폰의 오탐(false positive)을 줄여줍니다).
  2. FOV가 해당 객체의 bounding box에서 최소 count_thres개의 변(edge)과 교차한다.

적어도 하나의 Phone이 두 조건을 모두 만족하면, 그 사람은 휴대폰을 보고 있는 것입니다.

설정

  • conf_thres: 0.5  (0 < conf_thres <= 1)
  • count_thres: 1  (1 <= count_thres <= 4)
  • fov_degree: 30  (FOV 크기, 단위: 도, 0 <= fov_degree <= 90)

데모

무작위로 생성된 시선 벡터와 휴대폰 객체를 이용해 알고리즘이 동작하는 모습을 보여주는 예시 이미지입니다:

범례:

  • 녹색 벡터: FOV 경계
  • 하늘색 벡터: 시선 벡터(gaze vector)
  • 흰색 사각형: conf_thres 미만인 객체
  • 노란색 사각형: 사람의 bbox 안에 있지만 FOV 밖에 있는 객체
  • 빨간색 사각형: 두 조건을 모두 만족하는 객체(보고 있는 휴대폰)
import math
import cv2
import numpy as np
from loguru import logger


def get_rotation(start_point, center_point, rad):
    """Rotate start_point around center_point by rad radians (counter-clockwise)."""
    T = [0, 0]
    T[0] = (start_point[0] - center_point[0]) * math.cos(rad) \
         - (start_point[1] - center_point[1]) * math.sin(rad) \
         + center_point[0]
    T[1] = (start_point[0] - center_point[0]) * math.sin(rad) \
         + (start_point[1] - center_point[1]) * math.cos(rad) \
         + center_point[1]
    return T


def find_angle(start_point, end_point):
    """Angle of vector start_point->end_point w.r.t. Ox axis (clockwise)."""
    return math.atan2(end_point[1] - start_point[1], end_point[0] - start_point[0])


def is_anglerange_in_fovrange(fov_min, fov_max, angle_1, angle_2):
    """Check if [min(angle_1,angle_2), max(angle_1,angle_2)] overlaps [fov_min, fov_max].

    Constraints:
        0 <= fov <= math.pi / 2   (fov_min <= fov_max)
        -math.pi <= angles <= math.pi
    """
    angle_min = min(angle_1, angle_2)
    angle_max = max(angle_1, angle_2)

    if fov_min <= 0 and fov_max >= 0:
        if fov_min >= -math.pi / 2:         # -pi/2 <= fov_min <= 0, 0 <= fov_max <= pi/2
            if angle_max < fov_min:
                return False
            elif angle_max <= fov_max:
                return True
            elif angle_max <= fov_min + math.pi:
                return angle_max - math.pi <= angle_min <= fov_max
            else:
                return fov_min <= angle_min <= fov_max
        else:                                # -pi <= fov_min < -pi/2
            if angle_max <= fov_min:
                return True
            elif angle_max <= 0:
                return angle_min <= fov_min
            elif angle_max < fov_max:
                return angle_min <= angle_max - math.pi
            else:
                return True
    else:
        if fov_max <= 0:                     # fov_min <= fov_max <= 0
            if angle_max < fov_min:
                return False
            elif angle_max <= fov_max:
                return True
            elif angle_max <= fov_max + math.pi:
                return angle_max - math.pi <= angle_min <= fov_max
            else:
                return fov_min <= angle_min <= angle_max - math.pi
        else:                                # 0 <= fov_min <= fov_max
            if angle_max < 0:
                return False
            elif angle_max < fov_min:
                return angle_min <= angle_max - math.pi
            elif angle_max <= fov_max:
                return True
            else:
                return angle_max - math.pi <= angle_min <= fov_max
    return False


def is_overlapped(bbox1, bbox2):
    """Check if two bounding boxes [xmin, ymin, xmax, ymax] overlap."""
    h = (bbox1[0] <= bbox2[2] and bbox1[0] >= bbox2[0]) or \
        (bbox2[0] <= bbox1[2] and bbox2[0] >= bbox1[0])
    v = (bbox1[1] <= bbox2[3] and bbox1[1] >= bbox2[1]) or \
        (bbox2[1] <= bbox1[3] and bbox2[1] >= bbox1[1])
    return h and v


def find_intersect_obj_indices(gaze_start, gaze_end, objects, bbox,
                               fov_degree=30, conf_thres=0.5, count_thres=1):
    """Return indices of objects whose bounding boxes intersect the gaze FOV.

    Args:
        gaze_start, gaze_end: gaze vector endpoints (x, y)
        objects: list of [xmin, ymin, xmax, ymax, conf]
        bbox: human bounding box [xmin, ymin, xmax, ymax]
        fov_degree: FOV half-angle in degrees (0 <= fov_degree <= 90)
        conf_thres: minimum object confidence (0 < conf_thres <= 1)
        count_thres: minimum intersecting edges (1 <= count_thres <= 4)
    """
    rad = math.pi * fov_degree / 360
    fov_p1 = get_rotation(gaze_end, gaze_start, rad)
    fov_p2 = get_rotation(gaze_end, gaze_start, -rad)

    fov_a1 = find_angle(gaze_start, fov_p1)
    fov_a2 = find_angle(gaze_start, fov_p2)
    fov_amin, fov_amax = min(fov_a1, fov_a2), max(fov_a1, fov_a2)

    intersect_idx, outside_idx, unseen_idx = [], [], []

    for idx, obj in enumerate(objects):
        if not is_overlapped(obj, bbox):
            outside_idx.append(idx)
            continue

        if obj[4] >= conf_thres:
            corners = [(obj[0], obj[1]), (obj[0], obj[3]),
                       (obj[2], obj[1]), (obj[2], obj[3])]
            angles = [find_angle(gaze_start, c) for c in corners]

            count = sum([
                is_anglerange_in_fovrange(fov_amin, fov_amax, angles[0], angles[1]),  # top
                is_anglerange_in_fovrange(fov_amin, fov_amax, angles[2], angles[3]),  # bottom
                is_anglerange_in_fovrange(fov_amin, fov_amax, angles[0], angles[2]),  # left
                is_anglerange_in_fovrange(fov_amin, fov_amax, angles[1], angles[3]),  # right
            ])

            if count >= count_thres:
                intersect_idx.append(idx)
            else:
                unseen_idx.append(idx)

    return fov_p1, fov_p2, intersect_idx, outside_idx, unseen_idx


def generate_object(image_size):
    xmax = np.random.randint(1, image_size)
    xmin = np.random.randint(xmax)
    ymax = np.random.randint(1, image_size)
    ymin = np.random.randint(ymax)
    return [xmin, ymin, xmax, ymax, np.random.rand()]


def generate_gaze(bbox):
    while True:
        sx = np.random.randint(bbox[0], bbox[2])
        sy = np.random.randint(bbox[1], bbox[3])
        ex = np.random.randint(bbox[0], bbox[2])
        ey = np.random.randint(bbox[1], bbox[3])
        if sx != ex or sy != ey:
            break
    return (sx, sy), (ex, ey)

소형 객체 Recall을 위한 Slicing 기반 전처리

2026년 7월 21일

문제

표준 객체 탐지기(object detector)는 고정된 입력 해상도(예: 640×640)로 리사이즈된 이미지로 학습됩니다. 원본 이미지가 고해상도이고 관심 객체가 작거나 카메라에서 멀리 떨어져 있는 경우 — 멀리 있는 보행자, 작은 컨테이너 코드, 철도 플랫폼 가장자리 근처의 작업자 등 — 이 리사이즈 단계는 이러한 객체를 불과 몇 픽셀 수준으로 줄여버립니다. 학습 신호 대부분은 크고 인식하기 쉬운 객체에 지배되며, 작은 객체에 대한 recall(재현율)이 떨어지게 됩니다.

SAHI를 한마디로

SAHI(Slicing Aided Hyper Inference)는 이 문제를 추론 시점(inference time)에 해결합니다: 탐지기에 다운스케일된 이미지 한 장을 넣는 대신, 전체 해상도 이미지를 겹치는 타일(tile)들로 자르고, 각 타일에 대해 전체 해상도로 독립적으로 탐지를 수행한 뒤, 모든 타일 단위 탐지 결과를 NMS로 원본 이미지 좌표로 다시 병합합니다. 다운스케일링으로 사라졌을 작은 객체들이 이제 각 타일에서 훨씬 더 큰 비중을 차지하게 되어, 탐지기가 실제로 다룰 수 있는 픽셀을 갖게 됩니다.

이 아이디어를 학습 데이터에 적용하기

추론 시점에 여러 번 슬라이스 패스를 실행하는 것은 비용이 큽니다 — 이미지당 순전파(forward pass) 횟수를 배로 늘리는데, 이는 실시간 배포 예산과 상충됩니다. 그래서 추론 시점에 슬라이싱을 하는 대신, 같은 아이디어를 파이프라인의 더 이른 단계로 옮겼습니다: SAHI 방식의 슬라이싱을 사용해 더 나은 학습 세트를 구축하고, 추론 자체는 단일 전체 이미지 순전파로 유지하는 것입니다.

상위 수준에서, 이 전처리 단계는 다음과 같습니다:

  1. 각 학습 이미지를 (설정 가능한 타일 크기와 겹침 비율로) 겹치는 타일들로 자릅니다.
  2. ground-truth box를 타일 좌표로 다시 매핑하며, 가시성(visibility)/IoU 임계값 이상의 box는 유지하고 나머지는 버리거나 잘라냅니다.
  3. 작은 객체 인스턴스를 포함하는 타일을 오버샘플링(oversample)하여, 학습 분포가 인식하기 쉬운 대형 객체 크롭(crop)에 지배되지 않도록 합니다.
  4. 잘라낸 crop을 원본 전체 해상도 이미지와 다시 섞어, 모델이 여전히 전역적인 장면 맥락(global scene context)을 보고 타일 스케일의 통계치에 overfit되지 않도록 합니다.

이미 소형 객체 민감도를 위해 더 높은 해상도의 P2 탐지 헤드로 확장된 YOLOv8-p2와 YOLOv9n과 결합했을 때, 이 전처리 단계는 작고 먼 객체에 대해 의미 있는 recall 향상을 가져다주었으며, 동시에 추론은 여전히 단일 전체 이미지 패스로 유지되어 실시간 지연시간(latency)도 그대로 보존되었습니다.

예시 스케치

슬라이싱 + 재매핑 단계를 단순화한 스케치입니다(예시 목적이며, 실제 프로덕션 구현이 아닙니다):

def slice_image(image, boxes, tile_size=640, overlap=0.2, min_visibility=0.3):
    """Slice an image into overlapping tiles, remapping ground-truth boxes."""
    stride = int(tile_size * (1 - overlap))
    tiles = []

    for y in range(0, image.height, stride):
        for x in range(0, image.width, stride):
            tile_box = (x, y, x + tile_size, y + tile_size)
            tile_img = image.crop(tile_box)

            tile_boxes = []
            for box in boxes:
                clipped = clip_box(box, tile_box)
                if visibility(clipped, box) >= min_visibility:
                    tile_boxes.append(to_tile_coords(clipped, tile_box))

            tiles.append((tile_img, tile_boxes))

    return tiles
